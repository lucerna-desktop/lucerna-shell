# CI e configuração do repositório — desenho

Data: 2026-09-26. Item 12 das pendências (a parte de verificação; instalação e AUR ficam para depois).

## Objetivo

Todo PR para o `main` passa por quatro verificações automáticas — análise estática, regras do projeto, testes de unidade com cobertura e teste de fumaça — e só pode ser mesclado com todas verdes. O repositório fica configurado no padrão do galley, com o que faltou nele.

Critérios de sucesso:

- Um PR com aviso novo do qmllint, import entre features, função nova sem teste ou erro de QML ao carregar o shell é reprovado.
- O código atual passa limpo (os avisos de hoje são corrigidos neste trabalho, não tolerados).
- Os mesmos scripts rodam na máquina local (`dev/ci.sh`) e no GitHub, com o mesmo resultado.
- Ninguém, nem o administrador, empurra direto no `main` ou mescla com um check vermelho.

## Decisões tomadas

| Tema | Decisão |
| --- | --- |
| Escopo | Análise estática, regras do projeto, testes de unidade (com cobertura) e fumaça |
| Avisos existentes | Zerar agora e bloquear daí em diante |
| Ambiente no runner | Container `archlinux:latest` + pacman, com cache; sem imagem própria |
| Ambiente local | O mesmo `archlinux:latest` (não a imagem `lucerna-dev`), com o cache do pacman num volume por job; os jobs rodam com `env -i` e uma lista branca de variáveis |
| Categorias do qmllint | Todas escritas no `.qmllint.ini` em `warning`, inclusive as desligadas por padrão; exceção só com motivo medido |
| Conferência visual | `dev/test.sh`, versionado: container próprio `lucerna-polish` com a janela na tela do usuário; nunca o `lucerna-dev` |
| Obrigatoriedade | Os quatro checks obrigatórios, amarrados ao GitHub Actions |
| Merge | Só merge commit, com título e descrição do PR (já aplicado) |
| Licença | GPL-3.0 |
| `qmlformat` | Fora: reescreveria 60% dos arquivos e desfaz o estilo compacto do projeto |
| Hyprland no CI | Fora: não sobe sem GPU; a fumaça usa `sway` headless |
| QtTest | Fora: dentro do `qs` dá falso verde e o `qmltestrunner` não carrega o Quickshell |

## Estrutura

Os scripts em `ci/` são a fonte da verdade; o workflow só os chama.

```
ci/
  lint.sh          qmllint (com a árvore de módulos gerada) + shellcheck + ruff + JSON
  lib.sh           funções comuns: REPO_EXCLUDES, repo_files e copy_repo <destino> (a cópia gravável do repositório, sem o que o .gitignore lista; qmllint, unidade, cobertura, fumaça)
  rules.py         regras do projeto (só a biblioteca padrão do Python)
  unit.sh          prepara a cópia instrumentada, roda tests/runner.qml, confere o resultado
  smoke.sh         sway headless + shell + IPCs + capturas
  coverage.py      instrumenta, cruza e gera o relatório de cobertura
  tolerated.txt    avisos de ambiente tolerados pela fumaça (um padrão por linha, com motivo)
  packages/        uma lista de pacotes do pacman por job (lint.txt, rules.txt, unit.txt, smoke.txt)
  .qmllint.ini     todas as categorias, com nível explícito; MaxWarnings=0
tests/
  runner.qml       o harness: carrega os testes, check/eq, imprime PASS/FAIL e RESULT
  *.test.js        os testes, um arquivo por unidade (sun, format, nightschedule…)
  coverage.json    escopo da cobertura e exceções com motivo
dev/ci.sh          roda os scripts de ci/ localmente, no mesmo archlinux:latest do GitHub
dev/test.sh        conferência visual: container lucerna-polish, janela na tela do usuário
.github/workflows/ci.yml
```

### Workflow `ci.yml`

- Dispara em `pull_request`, em `push` no `main` e por agendamento semanal (segunda, 06:00 UTC), para pegar quebras vindas do Arch ou do Quickshell sem mudança no código. Também pode ser disparado à mão (`workflow_dispatch`).
- Quatro jobs independentes, com os nomes exatos dos checks obrigatórios: `lint`, `rules`, `unit`, `smoke`.
- Cada job roda em `container: archlinux:latest`, atualiza primeiro o `archlinux-keyring` e depois o sistema, instala a sua lista de `ci/packages/` e, no fim, limpa do cache o que não está instalado (`pacman -Sc`), com cache de `/var/cache/pacman/pkg` (`actions/cache`, chave com o hash da lista e a semana).
- O script do job roda como usuário comum, com o ambiente refeito por `env -i` e uma lista branca (`HOME`, `PATH`, `LANG`, `LC_ALL`, `TZ`, `USER`, `CI`, `CI_OUT`, `PYTHONDONTWRITEBYTECODE`): nada herdado do runner, do Docker ou da máquina muda o resultado. O `dev/ci.sh` roda os mesmos passos no mesmo `archlinux:latest`, com um volume Docker por job no lugar do `actions/cache`; por isso o `ci/tolerated.txt` medido na máquina vale no GitHub.
- `permissions: contents: read`; `concurrency` por ref, cancelando execuções antigas em PR; `timeout-minutes` em todo job; actions fixadas por SHA (o Dependabot atualiza).
- Artefatos: o `smoke` sempre sobe as capturas e o log do shell; `unit` sobe o relatório de cobertura; os outros sobem o log só quando falham. Os relatórios também vão para `$GITHUB_STEP_SUMMARY`.

## Os checks

### `lint`

- **qmllint** com os tipos resolvidos: copia a config para uma pasta temporária com um `.qmlls.ini` vazio, roda `QT_QPA_PLATFORM=offscreen qs -p` uma vez para o Quickshell gerar a VFS de módulos, copia a VFS seguindo os links (`cp -rL`; com symlinks o qmllint não acha o `qmldir`), acrescenta o que o `shell.qml` não alcança pelos imports (a VFS só tem isso: os `.js` e o `tests/runner.qml`), confere que a árvore tem os mesmos `.qml` do repositório, põe o `.qmllint.ini` na raiz e roda o qmllint em todos os `.qml` com `-I` na árvore e em `/usr/lib/qt6/qml`.
- `.qmllint.ini`: `MaxWarnings=0` e todas as categorias do qmllint escritas uma a uma, em `warning` — inclusive as dez que o qmllint 6.11.2 deixa desligadas por padrão (`CompilerWarnings`, `LintPluginWarnings`, `Shadow`, `Void`, `UseProperFunction`, `FunctionUsedBeforeDeclaration`, `ImportFileSelector` e as três `AttachedPropertyReuse`) e as duas que ficam em `info`, que o filtro descartaria (`MultilineStrings`, `UnusedImports`). O `lint` falha se o qmllint instalado tiver uma categoria que o `.ini` não cita (uma versão nova pode trazer outra desligada). O 6.12.0 trouxe nove (`BlockScopeVarDeclaration`, `DeferredPropertyId`, `EnumKeyCase`, `IdShadowsMember`, `InlineComponentEnums`, `QtDesignStudio.TranslationFunctionMismatch`, `RenamedType`, `Syntax`, `TypeInstantiatedRecursively`), todas em `warning`; `LintPluginWarnings` e `TranslationFunctionMismatch`, que o 6.12 não tem mais, ficam para o 6.11. Desligados só os falsos positivos comprovados — `UncreatableType` (PanelWindow ganha backend em tempo de execução), `UnresolvedType` (tipos do Quickshell sem informação completa) e `BadSignalHandlerParameters` (`Process.onExited` sem `QProcess::ExitStatus` nos qmltypes) — e as categorias que a medição mostrar inviáveis de zerar, cada uma com o motivo no `.ini` e registrada aqui. Todo o resto bloqueia, inclusive imports sem uso.
  - Exceção medida (Tarefa 7 do plano, 2026-09-26, qmllint 6.11.2, tudo em `warning`): `CompilerWarnings`, os avisos do compilador de QML para C++ (qmlcachegen), que o Quickshell não usa (carrega o QML em tempo de execução). Eram 3 536 em 166 arquivos, sem sobreposição: 288 `Instruction … not implemented` (221 de `try`/`catch`/`finally`, 67 de `delete`, spread e afins), limitação do compilador, sem QML que os tire; 139 `… can be shadowed` em tipos do Quickshell e 12 `Cannot resolve the argument type QProcess::ExitStatus`, que vêm dos qmltypes do Quickshell; 989 `from ThemeManager::… with type QObject`, que somem com a Tarefa 21; 151 `Cannot access value for name …`, os mesmos pontos dos `unqualified` (Tarefas 22 a 27); 1 856 de tipos (1 475 `… QVariant`/`QJSValue` e 381 de anotação de tipo) em 113 arquivos, que pedem tipar os dados de modelo e anotar cada função, sem efeito no shell; e 101 de outros tipos (24 de `Anim::tokens` com tipo `QObject`, 10 de `QQuickItem::parent`, sobrecargas ambíguas). Os 439 dos dois primeiros grupos (288 + 139 + 12) não têm correção no QML: com a categoria ligada, o gate nunca ficaria verde. As outras categorias medidas ficam em `warning` e são zeradas nas Tarefas 21 a 28: 1 140 `missing-property`, 169 `unqualified`, 24 `unused-imports` e um aviso cada em `shadow`, `use-proper-function` e `Quick.attached-property-reuse`; zero nas demais. O `lint` reprova qualquer categoria fora de `warning` que não seja uma dessas quatro (`UncreatableType`, `UnresolvedType`, `BadSignalHandlerParameters`, `CompilerWarnings`).
  - Exceção pontual (Tarefa 24, qmllint 6.11.2; revista no 6.12.0): supressão `// qmllint disable unqualified missing-property` só na linha da margem do `PanelWindow`, em um arquivo, uma linha: `margins.top: 90` no `MonitorConfirm.qml` (antes um bloco `margins {`; no 6.12 o aviso cai nas linhas de dentro, que a supressão na linha do bloco não cobre; o `Osd.qml` e o `NotificationPopups.qml` tinham as suas, e saíram com o conteúdo deles para a janela da forma). É falso positivo: o grupo `margins` do `PanelWindow` não vem por inteiro nos qmltypes do Quickshell (o módulo da janela declara `Margins` como tipo opaco, `isTypeOpaque`). O 6.11 acusa `unqualified` (`unknown grouped property scope margins`) e o 6.12, `missing-property` (`Could not find property "top"`); a supressão cita as duas para o lint passar nos dois. Quando o CI deixar de testar o Qt 6.11, tira-se o `unqualified` da linha e do `QMLLINT_ALLOWED_COMMENT`. Mantém-se o declarativo (uma margem reativa não aceita a atribuição imperativa). Regra: nenhuma outra supressão do qmllint sem entrada neste spec. A regra `supressões` do `ci/rules.py` confere isso: aceita só essa linha (arquivo e linha, na lista `QMLLINT_ALLOWED`) e reprova qualquer outro `qmllint disable` ou `enable`, seja numa linha sozinha, de outra categoria ou em outro arquivo.
- **shellcheck** em `ci/`, `dev/` e `services/scripts/`.
- **ruff** (`check` e `format --check`) em `dev/themes.py` e `ci/*.py`.
- **JSON**: cada `themes/*.json` tem as chaves obrigatórias (nome, cores completas, fontes, papel de parede, hyprland); `themes/shaders/effects.json` só aponta para `.qsb` que existem.

### `rules`

`ci/rules.py`, cada regra com mensagem em PT-BR apontando arquivo e linha:

1. **Camadas**: `features/*/ui` não importa `qs.services`; uma feature não importa outra (`qs.features.<outra>`); `core/` não importa `qs.features` nem `qs.services`.
2. **Acentos**: uma lista de palavras comuns sem acento (`nao`, `voce`, `configuracao`, `configuracoes`, `funcao`, `padrao`, `tambem`, `ate`, `ja`, `so`…) procurada em strings e comentários de `.qml`, `.sh`, `.py` e `.md`, ignorando identificadores, caminhos e blocos de código. A lista fica no próprio script, com o critério de cada palavra.
3. **Espaços**: sem tab, sem espaço no fim da linha, com quebra de linha no fim do arquivo, sem CRLF (em arquivos de texto do repositório).
4. **Shaders em dia**: recompila cada `themes/shaders/*.frag` com o mesmo comando do `dev/shaders.sh` e compara com o `.qsb` do repositório; reprova também um gerador que não produz nada e um `.qsb` órfão (sem `.frag`). A mensagem manda recompilar com o `qsb` do CI (`dev/ci.sh shell rules`).
5. **Temas em dia**: gera os JSON pelo `dev/themes.py` (com uma opção nova para gerar só os JSON, numa pasta dada) e compara com `themes/*.json`; um gerador que não produz nada reprova. As imagens ficam de fora: são lentas e dependem da versão do Pillow.
6. **Links locais**: imagens e arquivos citados nos `.md` existem.

### `unit`

- `tests/runner.qml` é um `ShellRoot` que importa os singletons testados, carrega os `tests/*.test.js`, oferece `check(cond, msg)` e `eq(real, esperado, msg)`, imprime `PASS`/`FAIL` por caso, `SUITE <nome> casos=N` por suíte e uma linha final `RESULT passed=N failed=M`, e sai com `Qt.callLater(() => Qt.exit(failed ? 1 : 0))` (no `onCompleted` o `Qt.exit` é ignorado).
- `ci/unit.sh` copia o repositório para uma pasta temporária, põe o runner ao lado do `shell.qml` (para os imports `qs.*` resolverem), aplica a instrumentação de cobertura e roda `TZ=America/Sao_Paulo QT_QPA_PLATFORM=offscreen timeout 60 qs -p runner.qml`. Passa só com código 0, a linha `RESULT … failed=0` com casos, **e**, para cada `tests/<nome>.test.js`, o `import "<nome>.test.js" as <Módulo>` no runner, o item `["<nome>", <Módulo>]` em `suites` e uma linha `SUITE <nome> casos=N` com N > 0 (um teste sem import, importado mas fora da lista de suítes, com o item apontando outro módulo, ou sem casos, reprova).
- Unidades cobertas no início: `core/time/Sun`, `core/format/Format`, `core/nightlight/NightSchedule` (horário fixo, pôr do sol, rampa, virada à meia-noite, "até a próxima virada"), `core/input/ShellShortcuts` e `InputActions`, as funções puras de `core/theme` e `core/launcher`, e as funções puras dos serviços (`Clipboard.decode`, `Monitors.parseMode`/`luaFor`/`logicalSize`, `Capture.geometryArg`, `Brightness.parse`, `Input.luaString`/`luaValue`; o plano lista todas: entra toda função de serviço que não chama processo, arquivo, D-Bus nem Hyprland).
- Testes que dependem de relógio usam datas fixas passadas às funções; nada lê a hora real.

### Cobertura

- `ci/coverage.py instrument` injeta `Cov.hit("<arquivo>:<função>")` na primeira linha de cada `function nome(...) {` dos arquivos no escopo (na cópia temporária, nunca no repositório) e acrescenta o import do singleton `Cov`, que só existe na cópia. `Cov` conta as chamadas e as imprime no fim da execução.
- `ci/coverage.py report` cruza as funções declaradas com as chamadas e gera o relatório por arquivo (porcentagem e funções não cobertas), em texto e em Markdown para o resumo do job.
- **Escopo que bloqueia** (`tests/coverage.json`): a lógica pura de `core/` e as funções puras dos serviços listadas. Arquivos novos em `core/` entram sozinhos; para ficar de fora, uma exceção explícita com motivo (ex.: `core/widgets` é interface, `core/config` é dado).
- **Gate**: 100% das funções do escopo chamadas por pelo menos um teste. Função nova no escopo sem teste reprova o PR. Um escopo com 0 funções ou um log sem nenhuma linha `COV` também reprova (dariam 100% sem medir nada).
- **Informativo**: a mesma instrumentação roda no `smoke`, sobre todos os `.qml` (uma função fora do padrão em qualquer arquivo reprova, com `arquivo:linha`). A unidade roda de novo numa cópia separada, e o relatório junta unidade e fumaça e mostra a cobertura de todas as funções do shell, sem bloquear.
- Fora: cobertura por linha e por ramo (exigiria um parser de JavaScript).

### `smoke`

- Instala `sway` e tira a capability do binário (`setcap -r /usr/sbin/sway`; senão o container recusa o exec). Sobe com `WLR_BACKENDS=headless WLR_RENDERER=pixman WLR_LIBINPUT_NO_DEVICES=1`, uma saída de 1920×1080, sem Xwayland e sem swaybg (`xwayland disable`, `swaybg_command -`: o container não tem nenhum dos dois, o fundo é do próprio shell, e o sway registraria um ERROR para cada um); o socket é o `wayland-*` que ele abrir, detectado, não fixo.
- Roda o shell com `dbus-run-session` e `QT_QUICK_BACKEND=software`, instrumentado para a cobertura informativa. Espera "Configuration Loaded" no log (com timeout), não um tempo fixo.
- Abre por IPC cada painel (`launcher`, `dashboard`, `sidebar` em cada seção, `settings` em cada tópico, `themes`, `power`, `clipboard`, `capture`, `overview`), confere o `panels get` depois de cada um, fecha, e tira uma captura com `grim` de cada estado. Não há IPC que devolva a aba, a seção ou o tópico abertos (os de `dashboard`, `sidebar` e `settings` só abrem): isso fica com a conferência do log e as capturas.
- Todo `ipc call` e todo `grim` roda com `timeout 10`, e a espera do `dbus-run-session` depois do `qs kill` é um laço de 10 s: um shell travado vira uma falha com mensagem de timeout, e o `shell.log` inteiro (com o trecho do travamento) sobe no artefato, junto do `kill.log`.
- Depois do último passo, 5 s de repouso (para o que chega tarde cair no log) e o encerramento do shell com `qs kill --pid`, esperado com código 0 em 10 s; só então o log final (com o encerramento) é conferido, e é o mesmo que vai para o artefato. O sway e o shell rodam cada um no próprio grupo de processos (`setsid`) e só esses grupos são encerrados, nunca processos por nome.
- Reprova se: qualquer linha ERROR ou WARN não bater com `ci/tolerated.txt`; um `ipc call` sair com código ≠ 0; o `panels get` não trouxer o painel esperado; o shell cair ou não carregar.
- `ci/tolerated.txt` tem os avisos de ambiente medidos no log real da fumaça (Tarefa 18): sem Hyprland (`HYPRLAND_INSTANCE_SIGNATURE`, `hyprland_focus_grab_v1`, `XDG_CURRENT_DESKTOP`, o pedido `j/clients` do IPC do Hyprland), programas ausentes (`hyprctl`, `brightnessctl`, cada comando exato), D-Bus do sistema (NetworkManager, UPower, power-profiles, Bluetooth), rede e PipeWire indisponíveis. Cada padrão tem um comentário com o motivo e bate com a linha inteira. O Mesa (`ZINK`) e o `swaybg` da sonda não aparecem no log real (Qt em software, sway com pixman e `swaybg_command -`) e saíram.
- O aviso "got operation finished from dropped operation" (Tarefa 19) vinha do `FileView` de `config.json` em `core/config/Config.qml`: o `reload()` que o `watchChanges` disparava competia com a gravação assíncrona do `writeAdapter()`, o mesmo bug que perdia configurações. A correção (`blockWrites: true`, commit 055cc62) resolveu os dois: numa cópia isolada sem `blockWrites` o aviso volta a aparecer; com ele, 8 rodadas verdes da fumaça não o mostraram. Por isso não entra no `ci/tolerated.txt`: se voltar, a fumaça reprova.
- Limite conhecido: o que depende do Hyprland (workspaces reais, visão geral com janelas, `hyprctl`) não é exercitado.

## Zerar os avisos atuais

Feito antes de ligar o gate, em commits separados por categoria para o diff ser revisável:

- **ThemeManager tipado**: `colors`, `font`, `radius`, `spacing` e as demais propriedades `QtObject` viram `component` com tipo declarado (ex.: `component Colors: QtObject {…}` e `property Colors colors: Colors {}`). Isso resolve os cerca de 1 100 `missing-property` "on type QObject" sem mudar nenhum uso.
- **Acessos não qualificados** (169): `pragma ComponentBehavior: Bound` onde há componentes aninhados, com os ids qualificados; revisão manual do que a correção automática do qmllint (`-f`) propuser.
- **Propriedades via `parent`** (cerca de 18: `parent.parent.modelData`, `parent.h`, `target?.labelWidth`): trocar por ids ou propriedades declaradas.
- **Imports sem uso** (24), **shellcheck** (5 scripts) e o que ruff, regras e acentos apontarem.
- **Categorias que vinham desligadas** (`shadow`, `use-proper-function`, `Quick.attached-property-reuse` na sonda, e o que a medição achar): corrigidas no código, como as outras.
- Depois de cada categoria: o shell é reaberto no container de teste (`dev/test.sh`, `lucerna-polish`) e conferido na tela contra capturas de antes das correções, inclusive as telas que a fumaça não cobre (tela de bloqueio, popups de notificação, OSD, estilos da barra e do launcher, visão geral com janelas). O refactor do ThemeManager toca todas as telas; antes de cada `pragma ComponentBehavior: Bound`, procura-se componente que cruza arquivos, que o qmllint não vê.

## Configuração do repositório

Aplicada por `gh api`, depois que o PR do CI estiver verde e mesclado (o GitHub não aceita exigir um check que nunca rodou).

### Ruleset `main`

- Alvo: branch padrão. Lista de bypass vazia (vale para o administrador, como o `enforce_admins`).
- Exige PR, sem aprovação obrigatória (com um mantenedor só e sem bypass, uma aprovação exigida impediria qualquer merge).
- Checks obrigatórios `lint`, `rules`, `unit` e `smoke`, cada um com `integration_id: 15368` (GitHub Actions): outro app que publique um check com o mesmo nome não satisfaz a regra. `strict`: o PR precisa estar em dia com o `main`.
- Conversas do PR resolvidas antes do merge.
- Método de merge permitido: só merge commit.
- Bloqueia force-push e exclusão.

### Repositório

- Merge commit só (squash e rebase desligados), título e corpo do PR no commit (já aplicado); auto-merge e "atualizar branch" ligados; branch apagada após o merge.
- Wiki e projects desligados; issues ligadas.
- Dependabot security updates, secret scanning com push protection e relato privado de vulnerabilidades ligados.
- **Descrição**: "Shell de desktop para o Hyprland, feito em Quickshell (QML): barra, painéis, launcher, notificações, papel de parede animado, captura e gravação de tela, visão geral dos workspaces e configurações completas. Tudo em português."
- **Tópicos**: `hyprland`, `quickshell`, `qml`, `qt6`, `wayland`, `desktop-shell`, `linux`, `archlinux`, `rice`, `status-bar`, `app-launcher`, `notifications`, `animated-wallpaper`, `screenshot`, `pt-br`.

## Ordem de entrega

1. Scripts de `ci/`, harness e testes, `dev/ci.sh`, rodando local.
2. Zerar os avisos, categoria por categoria, conferindo o shell na tela.
3. Workflow e arquivos do repositório; PR com os quatro checks verdes.
4. Mesclar; aplicar ruleset, configurações, descrição e tópicos; conferir que um push direto no `main` é recusado e que um PR com check vermelho não pode ser mesclado.

## Riscos

- **Arch em movimento**: uma atualização do Quickshell ou do Qt pode quebrar o CI sem mudança no código. É intencional (o run semanal existe para isso); a correção vai num PR próprio.
- **Instrumentação por texto**: depende do padrão `function nome(...) {` numa linha. O `coverage.py` falha com mensagem clara se achar uma função que não consegue instrumentar, em vez de contar errado.
  - Limite do gate de cobertura: uma função declarada como propriedade (`property var f: x => …`) não é instrumentada e escapa da contagem. Hoje o único caso é `core/widgets/Slider.qml` (`property var format: v => …`), que está fora do escopo; detectar isso reprovaria a fumaça (`--all`) por causa desse caso.
